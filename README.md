# MegaOrbitals

A Paper plugin for Minecraft **26.1.2** with **1322 overpowered orbital strike cannons**, each one a completely different weapon: nukes, black holes, tornadoes, mob armies, terrain tools, minigames, curses, buffs and more. Cannon #201, **Omega**, fires every other cannon at once.

## Install

1. Build the jar (see below) or grab it from Releases.
2. Drop `MegaOrbitals-<version>.jar` into your server's `plugins/` folder.
3. Start the server. Configs are created in `plugins/MegaOrbitals/`.

## Commands

| Command | Who | What it does |
|---|---|---|
| `/orbital <cannon>` | ops | Fires a cannon at the block you're looking at (unlimited range) |
| `/orbital menu` | ops | Paged GUI of every cannon; click to take one (shift-click for 16) |
| `/orbital list [page]` | ops | Lists cannons, 40 per page |
| `/orbital search <word>` | ops | Finds cannons by name or description |
| `/orbital info <cannon>` | ops | Shows a cannon's description and settings file |
| `/orbital reload` | ops | Reloads `config.yml` and every cannon config |
| `/orbitalgive <cannon\|all> [player] [amount]` | ops | Gives cannon items |

Anyone holding a cannon item can **right-click** to fire it at the block they're looking at.

More commands:

| Command | What it does |
|---|---|
| `/orbital undo [all\|player]` | Puts back every block your last strike changed (or a player's, or all) |
| `/orbital history` | Lists strikes that can still be undone |
| `/orbital satellites` | Lists your satellites and their charge |
| `/orbitalgive binoculars\|satellite-item\|core:<tier>` | Gives the special items |

## Features

- **Undo / rollback.** Every block a strike changes is remembered. Use `/orbital undo`, or set `rollback.auto-restore-seconds` (or a cannon's own `auto-restore-seconds`) to put terrain back automatically.
- **Tiers and categories.** Each cannon is common, rare, epic or legendary, and sits in a category (explosives, mobs, terrain...). Both can be changed in its yml.
- **Crafting and drops.** Orbital Cores are crafted, each tier from the one below, or dropped by bosses (`drops:` in config.yml). Right-click a core to get a random cannon of that tier.
- **Spotter binoculars.** Left-click to mark a target. Your cannons then hit the mark wherever you fire them from.
- **Satellites** (off by default). Launch satellites that recharge over time. Firing a cannon item then needs a charged satellite over the target.
- **Menu tabs.** `/orbital menu` has category tabs, a tier filter and a chat search box.
- **Discord alerts** for big cannons, via a webhook.
- **Language files.** Every message is in `lang/en.yml`. Copy it to translate.
- **Update checker.** Ops are told in-game when a newer GitHub release is out.

## Releases

Pushing to `main` builds the jar with GitHub Actions. Pushing a tag such as `v1.3.0` (matching the `pom.xml` version) also publishes a GitHub Release with the jar attached.

| Permission | Default | Meaning |
|---|---|---|
| `megaorbitals.orbital` | op | Use `/orbital` |
| `megaorbitals.give` | op | Use `/orbitalgive` and take items from the menu |
| `megaorbitals.use` | everyone | Fire cannon items |
| `megaorbitals.immune` | nobody | Never targeted by cannons |
| `megaorbitals.bypass.cooldown` | op | Ignore cooldowns |
| `megaorbitals.cannon.<id>` | — | Needed per cannon when `cannons.per-cannon-permission` is on |
| `megaorbitals.undo` | op | Use `/orbital undo` and `/orbital history` |
| `megaorbitals.undo.others` | op | `/orbital undo` undoes anyone's last strike, not just your own |
| `megaorbitals.bypass.satellite` | op | Fire cannon items without a satellite |
| `megaorbitals.update` | op | Get update notifications |

## Configuration

- **`config.yml`** controls the worlds whitelist or blacklist and the master block-damage switch. It also sets damage multiplier, spawn protection, rate limit, item and per-cannon cooldowns, item behaviour, disabled cannons, announcements, logging and every message.
- **`configs/<cannon>.yml`**: one file per cannon. It holds the name, lore and item, the warning time and colour, `break-blocks`, `hurt-shooter`, and that cannon's own `settings:`. Every option is commented.

Big block edits are spread over several ticks (`general.blocks-per-tick`) to keep lag down.

## Building

Needs **JDK 25** and **Maven**.

```
mvn clean package
```

The jar ends up in `target/`. The build also regenerates `src/main/resources/configs/*.yml` from the cannon classes.

## The arsenal (1000 combo cannons)

Since 1.5.0, 1000 of the cannons are "arsenal" cannons: each one combines one of 40 **payloads**
(Blast, Inferno, Thunder, Frost, Gravity, Undead, Mending...) with one of 25 **patterns**
(Strike, Shower, Ring, Nova, Spiral, Chain, Mines, Comet, Volley...), e.g. *Frost Spiral* or *Undead Volley*.
Every one has its own config with `power`, `radius`, `count` and `interval-ticks`.
They are defined in `Arsenal.java`; the small classes in `cannons/` are generated by
`python tools/generate_arsenal.py` (add a payload or pattern there and re-run it).
Omega skips them unless its `include-arsenal` setting is true.

## Adding a cannon

Create a class in `src/main/java/dev/megaorbitals/cannons/` that extends `Cannon`:

```java
public final class MyCannon extends Cannon {
    public MyCannon() {
        super("&cMy Cannon", Material.TNT, "Description line");
        option("radius", 10, "Range.");
    }

    @Override
    public void strike(Strike s) {
        s.explode(s.at(), (float) d("radius") / 2, false);
    }
}
```

It's picked up automatically. Its id is the class name in lower case (`mycannon`), and its config is generated on the next build or server start. `Strike`, `Fx` and `Blocks` provide helpers for timers, targets, particles and lag-safe block editing.
